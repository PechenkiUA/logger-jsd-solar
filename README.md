# Логер для інвертора JSDSolar J4000HC

Локальний моніторинг і керування гібридним інвертором JSDSolar J4000HC через штатний
Wi-Fi-донгл Eybond — без хмари SmartValue / SmartESS.

Логер приймає з'єднання від донгла, опитує інвертор, зберігає показники в SQLite і
віддає вебсторінку зі схемою потоків енергії, графіком потужності та налаштуваннями
інвертора.

## Як це працює

Донгл — TCP-клієнт: він сам підключається до сервера, адреса якого записана в ньому
командою `AT+CLDSRVHOST1`, і далі лише відповідає на запити. Замість `iot.eybond.com`
ми вказуємо свій сервер.

```
інвертор ──RS232── донгл ──TCP :18899──> logger.py ──HTTP :8090──> браузер
```

Сервер загортає запити в кадри Eybond (функція 4, «прозора передача»), а всередині
йдуть текстові G-команди інвертора: `GPDAT0` повертає всі поточні показники,
`TCCV????` читає налаштування, `TCCV28.2` записує його. Назви команд, розкладку полів
і діапазони налаштувань узято з проєкту
[groove-max/ha-eybond-local](https://github.com/groove-max/ha-eybond-local).

## Що вміє

- Показники раз на кілька секунд: споживання, сонячні панелі, батарея, мережа, режим
  роботи, температура. Сторінка отримує їх через WebSocket (`/ws`) одразу після
  опитування; якщо з'єднання немає, вона сама переходить на звичайні запити.
- Графік потужності за 15 хвилин, годину, 6 або 24 години.
- Читання 25 налаштувань інвертора і запис 21 з них просто зі сторінки. Після запису
  значення перечитується з інвертора.
- Вхід за логіном і паролем (HTTP Basic).

## Запуск у Docker

Потрібні Docker з Compose і тунель Cloudflare для HTTPS.

1. Створіть тунель у Cloudflare (Zero Trust → Networks → Tunnels) і додайте йому
   Public Hostname із сервісом `http://logger:8090`.
2. Підготуйте налаштування:

   ```bash
   cp .env.example .env
   nano .env   # AUTH_PASSWORD і TUNNEL_TOKEN
   ```

3. Запустіть:

   ```bash
   docker compose up -d --build
   docker compose logs -f logger
   ```

4. Відкрийте на сервері порт `18899/tcp` і перенаправте донгл (див. нижче).

Сторінка буде доступна за адресою з тунелю. Порт 8090 назовні не публікується; на
самому сервері він слухає `127.0.0.1:8090`, тож за потреби до нього можна дістатися
через SSH-тунель: `ssh -L 8090:127.0.0.1:8090 user@server`.

Якщо тунель Cloudflare не потрібен, приберіть сервіс `cloudflared` з
`docker-compose.yml` і поставте перед логером власний HTTPS-проксі.

## Запуск без Docker

Потрібен лише Python 3.10 або новіший, сторонніх пакетів немає.

```bash
python logger.py 2      # число — інтервал опитування в секундах
```

Сторінка: <http://127.0.0.1:8090/>. Без пароля логер слухає лише локальну адресу.

## Налаштування донгла

Вкажіть у донглі адресу свого сервера:

```
AT+CLDSRVHOST1=<IP сервера>,18899,TCP
```

- Потрібна саме IP-адреса або домен без проксі Cloudflare: тунель передає лише HTTP,
  а донгл говорить сирим TCP.
- Донгл тримає одне з'єднання. Поки старий сервер не розірве свою сесію, на новий він
  нормально не перейде — зупиніть попередній логер або перезавантажте донгл.
- Щоб повернути хмару, запишіть назад `iot.eybond.com,18899,TCP`.

У логах після підключення має з'явитися:

```
dongle connected from <адреса>
heartbeat: I2000…, requests: {'ok': 1, …}
```

## Змінні середовища

| Змінна | За замовчуванням | Призначення |
|---|---|---|
| `MODE` | `control` | Тип роботи: `monitor` — лише моніторинг, налаштування показано без можливості зміни; `control` — моніторинг і зміна налаштувань |
| `AUTH_USER` | `admin` | Логін для сторінки |
| `AUTH_PASSWORD` | порожньо | Пароль. Без нього логер не стартує, якщо сторінка відкрита не лише для `127.0.0.1` |
| `POLL_INTERVAL` | `2` (у Docker `5`) | Секунд між опитуваннями |
| `LISTEN_PORT` | `18899` | Порт для донгла |
| `HTTP_HOST` | `127.0.0.1` (у Docker `0.0.0.0`) | Адреса, на якій слухає сторінка |
| `HTTP_PORT` | `8090` | Порт сторінки |
| `DB_PATH` | `inverter.sqlite` поруч зі скриптом (у Docker `/data/inverter.sqlite`) | Файл бази |
| `TUNNEL_TOKEN` | — | Токен тунелю Cloudflare, лише для `docker-compose.yml` |

## Безпека

- Сторінка змінює налаштування інвертора, зокрема напруги заряду. Ставте довгий
  пароль і не відкривайте її без HTTPS: пароль у Basic-авторизації не шифрується.
- Порт 18899 не захищений — протокол донгла пароля не має. Якщо вдома статична IP,
  дозвольте підключення до порту лише з неї.
- Трафік між донглом і сервером іде відкритим текстом.

## Діагностика

| У логах | Що це означає |
|---|---|
| `dongle connected` немає | Донгл не доходить до сервера: перевірте адресу в донглі, порт 18899 у брандмауері і чи не тримає його інший сервер |
| `heartbeat: None` | Донгл підключився, але не відповідає; найчастіше він ще працює зі старим сервером |
| `unexpected GPDAT0 reply … ''` | Донгл на зв'язку, але інвертор йому не відповідає: інвертор вимкнено, донгл від'єднано від COM-порту або зв'язок завис |
| `dongle disconnected … replaced by a new connection` | Донгл перепідключився, логер перейшов на нове з'єднання |

## Обмеження

- Перевірено на одному інверторі J4000HC (24 В) з донглом Eybond, налаштованим на
  `iot.eybond.com`. Інші моделі можуть мати інші команди чи діапазони.
- Запис налаштувань перевірено лише для струму заряду від мережі (`GCC`). Решта
  команд і діапазонів — з документації протоколу; що інвертор не приймає, він
  відхиляє сам.
- Пріоритет виходу, режим виходу, пріоритет заряду і тип батареї доступні лише для
  перегляду.
- Знак струму батареї та показники панелей і мережі не звірені з реальними значеннями.
- Старі показники не видаляються; база росте приблизно на 17 тисяч рядків за добу при
  інтервалі 5 секунд.
- Якщо зв'язок із сервером зникає, дані за цей час втрачаються: донгл нічого не
  зберігає.
